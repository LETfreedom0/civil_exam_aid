# 新省（新年度）岗位数据接入指南

> 目标：把某个省某一年度的公务员岗位表，从官网公告抓下来、清洗入库，进入
> `positions_full`（全量库），残疾专岗额外同步进 `positions`（专岗库）。

---

## 0. 为什么是「本地抓 + 本地导入」

| 环节 | 在哪跑 | 原因 |
|---|---|---|
| 抓取（访问 gxpta / beijing.gov.cn 等） | **必须本地** | 这类站点屏蔽境外 IP，GitHub Actions 的 runner 在境外，一律超时 |
| 写入（访问 supabase.co） | **本地也行** | 本机走 pooler 5432 通道可用；REST(443) 被 SNI 阻断 |

所以现在的标准做法是本地一条龙：

```bash
python scripts/scrape.py --export data/<源id>.json   # 抓 + 解析 + 导出
python scripts/import_local.py data/<源id>.json      # 直连 5432 入库
```

GitHub Actions 那条路（`push_data.py` → 推 `data/*.json` → `import.yml` 自动导入）
仍然保留，但只在你有特殊需要时用；日常本地跑更快。

**环境依赖**（换机器时先装）：

```bash
pip install -r scripts/requirements.txt   # requests / PyYAML / pandas / openpyxl / xlrd / pdfplumber
pip install psycopg2-binary               # 本地直连导入用
```

`.xls`（老格式）必须有 `xlrd`，`.xlsx` 用 `openpyxl`。

## 1. 找到公告页和职位表

搜索方式：

```
<省名> 2027年度 考试录用公务员 公告 site:gov.cn
```

要确认三件事：

1. **公告页能打开**，且正文里挂着附件
2. 附件是 **xlsx / xls**（PDF 暂不支持解析）
3. 记住**公告页 URL** 和**公告标题**——它们会写进 `positions_full.source_url`
   和 `announcements`，是用户「一键直达公告」的来源

> 附件有时在二级页面（如「附件下载」子页），确认好就直接用附件所在页当 `list_url`，
> 脚本会扫描该页所有 `<a href>` 里的 xlsx/xls。

## 2. 先看表结构，别急着写映射

下载一份真实表格，用下面这段看清楚 sheet、表头位置、列名：

```python
import pandas as pd
sheets = pd.read_excel("职位表.xlsx", sheet_name=None, header=None)
for name, df in sheets.items():
    print("---", repr(name), df.shape)
    print(df.iloc[:3].to_string())
```

重点看三件事：

- **表头在第几行**（0 基）→ 配置 `header_row`
- **sheet 是什么语义**：是城市（广西：区直/南宁/柳州…），还是职位类别
  （北京：普通/退役士兵/面向残疾人…）
- **列名有没有换行或空格**（北京整张表列名都是「职位\n代码」这种，脚本会自动规范化，
  但你在 `field_mapping` 里写**去掉换行后的名字**）

## 3. 写 `scripts/sources.yaml`

在 `sources` 列表里追加一段。完整字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一标识，建议 `<省缩写>-<站点>-<年度>`，如 `bj-rsks-2027` |
| `province_code` | ✅ | 6 位省码（北京 110000、广西 450000，见 `common/provinces.json`） |
| `name` | ✅ | 后台「数据来源」列显示的名字，**一定写中文全称** |
| `kind` | ✅ | `announcement`（官网公告页）/ `excel`（固定附件）/ `manual`（纯人工） |
| `enabled` | ✅ | 配好并验证通过后再改 `true` |
| `year` | ✅ | 考录年度 |
| `category` | ✅ | `0` 省考 / `1` 事业单位 / `2` 国考 / `3` 其他，自动写入 `exam_type` |
| `list_url` | ✅ | 公告页或附件所在页 |
| `announcement_title` | ○ | 公告标题；不填则从页面 `<title>` 自动提取 |
| `header_row` | ○ | 表头行号（0 基），默认 0；北京首行是标题，填 `1` |
| `sheet_as_city` | ○ | sheet 名当城市写入 `city`，默认 `true` |
| `sheet_identity` | ○ | sheet 名当「招考人群」判据，默认 `false`；北京填 `true` |
| `field_mapping` | ✅ | Excel 列名 → 库字段，逐省不同，必须核对真实表头 |

### `field_mapping` 常用目标字段

| 字段 | 中文常见列名 | 说明 |
|---|---|---|
| `position_code` | 职位代码 | 幂等键的一部分 |
| `recruit_unit` | 招录机关 / 单位名称 | |
| `region_dept` | 用人部门 / 内设机构 | |
| `position_name` | 职位名称 | 幂等键的一部分 |
| `quota` | 招考人数 | 自动转整数 |
| `education` / `degree` | 学历 / 学位 | |
| `major` | 专业（学科）类别 / 专业要求 | 注意全角括号 |
| `political_status` | 政治面貌 | |
| `unit_level` | 机构层级 / 职位层级 | |
| `position_nature` | 系统属性 / 机构性质 | |
| `position_type` | 职位类别 | |
| `essay_subject` | 职位类别（A/B/C 类） | 申论卷型 |
| `candidate_identity` | 职位招考对象 | 含「面向残疾人招考」 |
| `other_requirements` | 其他 / 其它条件 | **残疾人类别与等级常写在这里** |
| `grassroots_exp` | 基层工作经历 | |
| `fresh_grad` | 是否要求应届 | |
| `interview_ratio` | 面试比例 | |
| `phone1` / `phone2` | 咨询电话 | 单元格内换行自动压成 ` / ` |
| `description` | 职位简介 | |
| `max_age` | 年龄 | |

> 幂等键 `external_key` = md5(省码 | 年度 | 职位代码 | 单位 | 职位名)，
> 由脚本自动生成，**不要手工映射**，也不要映射到 `external_key`。

### 两个可照抄的范式

- **sheet = 城市 + 有「招考对象」列** → 广西，看 `gx-rsks-2026`
- **sheet = 职位类别 + 表头在第 2 行 + 无「招考对象」列** → 北京，看 `bj-rsks-2027`

## 5. 导出后先校验，再入库

```python
import json, collections
d = json.load(open("data/<源id>.json", encoding="utf-8"))
s = d["sources"][0]
rows = s["rows"]
print("公告:", s.get("announcement"))
print("行数:", len(rows), "| external_key 唯一:", len({r["external_key"] for r in rows}) == len(rows))
print("群体分布:", collections.Counter(r.get("candidate_identity") for r in rows).most_common(6))
print("缺失:", {k: sum(1 for r in rows if not r.get(k)) for k in ("position_code","recruit_unit","position_name","quota","education")})
print("quota 类型:", type(rows[0].get("quota")).__name__)
```

**四条硬指标**：

- 行数与该省公告的人数规模量级一致（差太多说明漏 sheet 或表头错位）
- `external_key` 全唯一（重复说明职位代码省内重号且单位名没取对）
- 关键字段缺失率为 0 或极低（`position_name` 大面积空 = `field_mapping` 写错）
- `quota` 是 `int`，不是字符串

## 6. 入库

```bash
python scripts/import_local.py data/<源id>.json
```

它做这几件事（和 Actions 用的 `import_data.py` 规则完全一致）：

1. `positions_full` upsert（`ON CONFLICT (external_key)`，重复跑不产生重复数据）
2. 自动打标：文本含「残疾人证 / 限残疾人 / 残疾人」→ `is_disability_only=true`，
   并解析 `disability_types`（肢体/视力/听力…）、`allowed_levels`（一至四级）、
   `audience_tags=['disabled']`，原文保留在 `disability_source_text`
3. 顺手识别「艰苦边远地区：是」→ `remote_area`，应届条件 → `fresh_grad`
4. 残疾专岗**同步写一份到 `positions`**（专岗库）
5. 登记 `data_sources`（按 `source_url` 去重）、`announcements`（按 url 幂等）、
   `notices`（公告页 + 附件两条记录）、`run_log`

## 8. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 0 条 / 附件找不到 | 附件不是 xlsx/xls，或链接在二级页 | 换 `list_url` 到附件实际所在页 |
| 字段大面积空 | 表头行不对，或列名带换行 | 设 `header_row`；`field_mapping` 用去换行的列名 |
| 只有部分行 | 表头以上有标题行被当数据 / 漏 sheet | 脚本会跳过表头以上；确认附件里的 sheet 数 |
| `.xls` 报错 | 缺 `xlrd` | `pip install xlrd` |
| 残疾专岗全是 false | 残疾信息不在「其他条件」列 | 补 `other_requirements` 映射；或看 sheet 名（`sheet_identity`） |
| 来源列显示英文代号 | 导入的 JSON 缺 `name` | 已在导出端修复；老 JSON 手工补 `name` 字段即可 |
| 重复导入 | — | 不用担心，按 `external_key` 幂等 |
| 附件抓不到（链接无 `.xls` 后缀） | 走 `/api-gateway/...download?fileUrl=` 这类包装链接（浙江/江苏/四川） | 现已按文件头魔数识别格式；自动发现仍抓不到时写进 `attachment_urls` |
| 附件是 zip 包 | 公告附件打包（广东） | 支持解包取内部 xlsx/xls，用 `zip_member_pattern` 只取「职位表」 |
| 同一工作簿各 sheet 表头行不同 | 有的压两行标题、有的三行（广东/江苏） | 逐 sheet 自动定位表头，无需设 `header_row` |
| 一个字段分散在多列 | 专业要求分「研究生/本科/大专」三列（广东） | `field_mapping` 同一字段给多列，用「；」拼接 |
| 幂等键撞车 | 职位代码短、各市独立编号（江苏 2 位代码） | 配 `key_fields`，把 `city`/`region_dept`/`major` 纳入键 |
| 详情页 404、附件抓不到 | 站点是 Vue/React 单页应用（上海） | 翻 `app.*.js` 找 `baseURL` 与接口路径，直接把附件地址写进 `attachment_urls`（见 8.6） |
| 专项岗位没打上残疾标 | 「招考对象」列写「不限」，群体口径只在 sheet 名上（上海） | 配 `sheet_identity_map`，按 sheet 名显式指定身份 |

## 8.5 一个站点挂几十份公告（以四川为例）

像四川这种「省级机关 + 21 市州 + 公安 + 法检 + 监狱 + 定向」各自发公告的省，不要手工写几十遍配置，走这三步：

1. **先摸专题页**。四川人事考试网的 2027 专题页一次列全 47 条公告，直接解析该页拿到 `标题 + 详情页 URL`，比搜索靠谱。
2. **批量探附件**。对每个详情页抓 `/front/download-*` 链接及其文字。注意两点：
   - 这类链接路径里没有扩展名，靠 `ATTACH_SUFFIX` 自动发现抓不到 → 必须写进 `attachment_urls`
   - 附件里常混「报考指南/填表说明」，按文字过滤掉，只留标题含「职位」的
3. **一把生成配置**。用脚本按「城市 + 类别」生成 `id / name / list_url / attachment_urls`，`field_mapping` 用一份 superset 复用——缺失的列 `map_row` 会自动跳过，多出来的模板不影响。

四川 45 个源就是这么生成的。真正需要人工判断的只有两点：`sheet_as_city` 要关掉（sheet 名是 `Sheet0`/`法院系统`，不是城市），以及城市从表内「地区、部门」列取。

另外这批表暴露了三个共性问题，现已修在采集器里：

| 问题 | 表现 | 修法 |
|---|---|---|
| 表头带排版换行 | 表头写成「职位\n名称」，表头定位失效 → 广元只出 5 条、自贡警察 0 条 | 定位前先去掉换行再比对关键词 |
| 单元格内排版换行 | 「执法\n勤务（一）」原样入库 | `map_row` 统一去掉行内换行（电话列改成 ` / `） |
| 表尾说明被当岗位 | 末尾「说明：除特别注明外…」整段落成一条记录 | 编码字段超过 24 字或以「说明」开头则跳过 |

> 教训：**每接一个省，先看最小和最大两个源的条数**。广元 5 条对其他市 100+ 条，一眼就能看出表头定位错了。

## 8.6 站点是单页应用（SPA），附件拿不到（以上海为例）

上海 `shacs.gov.cn` 是 Vue 单页应用：首页 HTML 只有 `<div id=app></div>`，正文和附件全靠 JS 异步加载。直接请求详情页 `/recruits/440` 返回 **404**，页面解析和 WebFetch 都只能拿到空的骨架。

**不要在这里放弃，去翻它的 JS。** 三步：

1. **找接口基址**。在 `static/js/app.*.js` 里搜 `baseURL`，上海是 `https://shacs.gov.cn/gwyj/api`。同文件里能看到一整块 `$newsBiz` 定义，形如 `getGwyColumn: ... rt(X, "/gwy-column-section.json", ...)`——**冒号后面的字符串就是接口路径**，一次能捞全。
2. **顺接口取数据**。上海这三个够用：
   - `/gwy-column-section.json?listChild=true` → 全部专题（`440` = 2027 年度考试录用公务员专题）
   - `/child-section-and-news.json?sectionId=440` → 专题下的栏目分组与文章列表（含 id / 标题 / 发布日期）
   - `/show-news.json?id=1465` → 文章详情，带 `attIds` / `attNames`
3. **拼附件地址**。附件下载规则在渲染文章的 chunk 里：`{address}/api/files/fetch?fid={attId}`。`address` 是页面里注入的站点前缀，上海为 `https://shacs.gov.cn/gwyj`。

拿到 `https://shacs.gov.cn/gwyj/api/files/fetch?fid=93e10a70-…` 后，直接写进 `attachment_urls` 即可——**这类链接没有扩展名，但采集器已按文件头魔数识别格式**。

配套的两个配置点：

```yaml
    sheet_as_city: false        # sheet 是「招录类别」不是城市
    sheet_identity_map:         # 三张专项表的「招考对象」列写的是「不限」，
      残疾人: 残疾人专项招录      # 群体口径只体现在 sheet 名上，必须显式指定
      服务基层项目: 服务基层项目人员
      高校毕业生退役士兵: 高校毕业生退役士兵
```

上海简章一个 xls 装 9 张表（公务员/参公/行政执法/服务基层项目/市外办非通用语/公安机关特警/残疾人/警务技术类人民警察/高校毕业生退役士兵），每张表前两行都是标题与说明，表头在第 3 行——`_detect_header_row` 会自动定位，无需配 `header_row`。

> 这类站点还有一个坑：抓取时列表页 404 会直接抛异常中断。已改成「配了 `attachment_urls` 就降级继续」，公告页地址仍保留给 `source_url` 跳转。
